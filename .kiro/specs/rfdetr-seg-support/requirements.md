# Requirements Document

## Introduction

DDA supports RF-DETR **object detection** end to end. `rfdetr-training-and-transfer-learning` added the SageMaker entry point `datasets/detection_training/train_rfdetr.py`, the shared vocabulary in `edge-cv-portal/backend/layers/shared/python/detection_training.py` (`DETECTION_ARCHES = ('yolo', 'rf_detr')` at `:42`, `RFDETR_SIZES` nano/small/medium/large at `:92-97`), the `rf_detr_object_detection` device manifest (`build_detection_device_manifest`, `:548-642`) and its parity test; `detector-checkpoint-import` added `.pth` conversion in a network-isolated job (`datasets/detection_training/export_checkpoint.py`, `convert_rfdetr` at `:837`). On the device `RfDetrDetectionPostProcessor` is registered as stage type `rf_detr_object_detection` (`src/backend/lyra_science_processing_utils/model_processors/__init__.py:62`) and its boxes ride the `task = object_detection` contract of the Triton base model (`src/backend/dda_triton/resources_for_copy/lfv_model_template.py:312-372`).

**RF-DETR-Seg** (Roboflow's instance-segmentation RF-DETR, shipped in the pinned `rfdetr==1.10.1`: `datasets/detection_training/requirements-rfdetr.txt:6`, `edge-cv-portal/detector-export-image/requirements.lock:58`) has only an import-only path from commit `5ebe51bc` (2026-07-04). Smart Import accepts an already exported 3-output ONNX (`model_converter.inspect_onnx_model`, `n_out >= 3` at `edge-cv-portal/backend/functions/model_converter.py:652-661`), writes a `rf_detr_semantic_segmentation` stage with no `task` key and `pixel_level_classes` placeholders (`:993-1015`), and the device's `RfDetrSemanticSegmentationPostProcessor` (registered as `"financier"` at `model_processors/__init__.py:64`) flattens the per-query masks into **one semantic index mask** by per-query argmax and nearest-neighbour resize, discarding the boxes and all instance identity (`rf_detr_semantic_segmentation_postprocessor.py:79-119`). Nothing else exists: `train_rfdetr.py` has no Seg size classes (`SIZE_CLASSES`, `:82-87`) and its `verify_two_outputs` is FATAL on any output count other than 2 (`:532-555`); checkpoint conversion rejects Seg checkpoints by name (`detector_conversion.py:209-210`, `export_checkpoint.py:854-864`) and lists `RFDETRSegXLarge`/`RFDETRSeg2XLarge` as PML-licensed (`detector_conversion.py:124`, `export_checkpoint.py:120`); the Portal has zero tests for the seg path; the labeling system has no instance modality (Segmentation stores `regions: [{class, rle}]` and exports ONE semantic palette PNG per image: `dda_manifest.py:20-47`, `_serialize_segmentation` at `:434-456`); and the COCO writer in `datasets/manifest_to_detector_dataset.py:383-391` emits `bbox`/`area`/`iscrowd` with no `segmentation` field.

This spec makes RF-DETR-Seg a first-class model family in DDA, in the shape the owner decided (D1–D5 below): both instance and semantic output selectable per model; training from the published Seg weights and fine-tuning of a prior/imported checkpoint; `.pth` import and conversion; hardening of the existing ONNX Smart Import; a new instance-segmentation labeling modality and manifest format; all six Seg sizes. It extends the patterns the two precedent specs set rather than inventing parallel ones: new entries in the arch-keyed constant maps of `detection_training.py`, a second entry-point verifier beside `verify_two_outputs`, an extension of `tests/test_detection_manifest_parity.py`, new size/prefix tables beside the detection ones in `detector_conversion.py` and `export_checkpoint.py`, the same Export_Image with its pins unchanged unless a Seg export proves otherwise, `training_metadata.json` `device_manifest_hints` as the trainer-to-packager channel, and a per-architecture on-device verification task at the end.

Unlike the two precedents, this feature **requires a LocalServer build for every architecture** (D5, Requirement 14): the decoder, the Triton base/marshal templates, the device DB and run-preview readers and the HMI live in the LocalServer image, and the device result contract changes (Requirement 10). The published JP6 component `model-rf-detr-seg-nano-jetson-xavier-jp6` (stage type `rf_detr_semantic_segmentation`, READY on a JP6 AGX Orin per `.kiro/specs/jp6-vllm-kv-cache-oom-regression/tasks.md:874`, with "NO inference was exercised" at `:998`) has no byte-compatibility claim on this spec (D5).

### Out of scope

- **Other segmentation families.** Ultralytics YOLO-seg checkpoints (`SegmentationModel`, head `Segment`) stay rejected by conversion (`detector_conversion.py:102-118`); generic semantic `[B, C, H, W]` ONNX imports stay as they are (`MODEL_TYPES['segmentation']`, `model_converter.py:137-140`); the Marketplace/LFV `segmentation` and `segmentation-robust` training path (`training.py:800-802`) is untouched and byte-identical.
- **RF-DETR keypoint models** (`RFDETRKeypoint*`, rejected at `export_checkpoint.py:121, 863`).
- **Converting existing semantic Segmentation datasets into instance datasets.** The semantic palette PNG has no instance identity; splitting it by connected components is wrong for touching instances. Existing Segmentation labeling jobs and `anomaly-mask-ref` manifests keep feeding only the LFV path. A one-way "derive instances" import is a follow-up candidate.
- **TensorRT execution and rectangular inputs** — exactly as the detection precedent: `device: "tensorrt"` stays opt-in and never written by the converters; the Seg path is square-only.
- **Dynamic batch, multi-image inference, video-rate mask streaming.** Static batch 1, as every RF-DETR export in DDA (`train_rfdetr.py:471-479`).
- **Changing the device ONNX IR cap.** `EDGE_MAX_ONNX_IR_VERSION = 10` (`datasets/detection_training/_common.py:374`) stays; Seg exports are capped the same way.
- **New MCP tools.** Existing tool schemas gain enum values (Requirement 13); no tool is added, so the pinned tool counts do not move.
- **Evaluating weight licences beyond the package metadata.** The spec corrects DDA's PML list to what rfdetr 1.10.1 and its PyPI README state (D4); it does not audit Roboflow's weight hosting terms.
- **Interactive (on-canvas) SAM inference** (O7 a chose the polygon tool). The existing `sam` / `grounded-sam` families stay batch pre-labelers (`.kiro/specs/grounded-sam-autolabel/requirements.md:5-7`) and feed the new modality (Requirement 2.4).
- **A device run-time Output_Mode override** (O15 a: the mode is fixed per component version) and **a third Output_Mode** (for example boxes-only from a Seg model; use a detection model).
- **Changing the detection decoders' behaviour** beyond the three-class tie-break fix of Requirement 9.2; YOLO and RF-DETR detection results stay byte-identical.

## Glossary

Terms from the precedent specs keep their meaning (Detection_Training_Job, Detection_Arch, Detection_Artifact, Base_Model, Fine_Tunable_Checkpoint, Imported_Model, Checkpoint_Probe, Conversion_Job, Export_Image, Conversion_Record, Fleet_Floor_Runtime, Parity_Check, Network_Input). New or refined terms:

- **RF_DETR_Seg**: Roboflow's instance-segmentation RF-DETR as shipped in `rfdetr==1.10.1`: classes `RFDETRSegNano|Small|Medium|Large|XLarge|2XLarge` (plus the deprecated `RFDETRSegPreview`, never offered), `segmentation_head: True`, `mask_downsample_ratio = 4`.
- **Seg_Size**: one of `nano` (312), `small` (384), `medium` (432), `large` (504), `xlarge` (624), `2xlarge` (768); the number is the native square resolution. All six are Apache 2.0 (D4). Decoder query counts: 100, 100, 200, 200, 300, 300.
- **Seg_Input_Block**: the divisor a Seg network input must satisfy, `patch_size × num_windows`: every Seg size has `patch_size = 12`; `nano` has `num_windows = 1` (block **12**), the other five have `num_windows = 2` (block **24**) — rfdetr 1.10.1 `src/rfdetr/config.py:879-973` (`RFDETRSegNanoConfig` … `RFDETRSeg2XLargeConfig`), enforced by `detr.py:388-394` for detection and Seg alike (`web-answers.md` WQ-req-author-2). It is NOT the detection block of 32 (`detection_training.py:104`, `detector_conversion.py:88` `INPUT_STEP`, `train_rfdetr.py:94` `RESOLUTION_STEP`), which rejects the native 312, 432, 504 and 624 and passes 384 and 768 only by coincidence.
- **Seg_Output_Contract**: the three ONNX outputs of a Seg export: boxes `[1, Q, 4]` normalised cxcywh, logits `[1, Q, C+1]` (trailing background slot — rfdetr's own ONNX helper drops the LAST slot as background, `export/_onnx/inference.py:148, 263` at 1.10.1 — the same convention `verify_two_outputs` enforces for detection at `train_rfdetr.py:532-595`), masks `[1, Q, R/4, R/4]` raw logits from `SegmentationHead.forward_export` (`models/heads/segmentation.py:317-336`; `mask_downsample_ratio = 4`, `config.py:515`). rfdetr sets the names `dets`, `labels`, `masks` and, with `dynamic_batch=False`, declares no dynamic axis, so dims are static by construction (`detr.py:1800-1813`; `web-answers.md` WQ-req-author-3, not reproduced live). DDA identifies the tensors **by shape first** because an older export lost a name (GitHub issue roboflow/rf-detr#405; `rf_detr_semantic_segmentation_postprocessor.py:19-22`), and by name or recorded order second — necessary when `C + 1 == 4` (a three-class model), where boxes and logits have the same shape.
- **Output_Mode**: the per-model choice D1 requires: `instance` (boxes + one mask per detection) or `semantic` (one class-indexed mask per image, today's behaviour). Set at model creation (training, conversion or import request field `output_mode`, default `instance`), stored on the record as `detection.output_mode`, written into the manifest as `detection.output_mode` and implied by the Seg_Stage_Type (O15 a, O16 a). Switching mode means re-packaging as a new component version; the device has no run-time override.
- **Instance_Result**: one detected object with `class_index`, `class_label`, `confidence`, `bounding_box` in source-frame pixels, `mask_rle` (Canonical_RLE at source-frame resolution) and `mask_area` (foreground pixel count) (O2 b).
- **Composite_Mask**: the single class-indexed mask (0 = background, class i → index i+1) painted from the kept instances' binary masks ascending by confidence (higher confidence wins overlaps). In semantic mode the decoder returns it as `AnomalyResult.mask` and the base model colours it (`convert_index_mask_to_color_mask`, `lfv_model_template.py:394`) into the palette RGB `mask` tensor → `<capture_id>.mask.png` (`:374-420`, `marshal_for_capture_template.py:319-342`). In instance mode the decoder returns only the Instance_Results and the base model's `__build_detection_tensors` paints the Composite_Mask itself from `Instance_Result.mask` (Requirement 10.1); no decoder output carries it.
- **Detection_List**: the JSON list in the Triton `anomalies` tensor whose first entry carries `bounding_box`; the marshal's `_is_detection_list` (`marshal_for_capture_template.py:161-170`) routes on it and emits the `{"detections": {...}}` block, `overlay.jpg` and the detections sidecar (`:437-492`). **Two shapes carry the same entries, and this document names which surface carries which:** the *list form* (a JSON array in detection order) is what the Triton tensor carries and what Requirement 10.5b stores in the device DB and returns from the result-history API and the edge MCP; the *map form* `{"0": {...}, "1": {...}}` (contiguous string keys, `marshal_for_capture_template.py:447-469`) is what the marshal writes into the capture-record label block and the sidecar and what `save_image_object` places in the live-result dict (`inference_results_utils.py:97`), read by the HMI with `Object.values` (`live-result/LiveResultCard.tsx:70`). Entries are identical in both forms (`class_index`, `class_label`, `bounding_box`, `confidence`, plus `mask_rle`/`mask_area` for instances).
- **Instance_Modality**: the new labeling task type (D3) whose annotations hold one region per object instance with a class, beside the existing `Classification`, `Segmentation` and `ObjectDetection` task types (`labeling.py:360`, `AnnotationCanvas.tsx:65-66`).
- **Instance_Manifest**: the Ground Truth-style manifest line the Instance_Modality exports (O8 a): `source-ref`, an `instance-segmentation` attribute `{image_size: [{width, height, depth: 3}], annotations: [{class_id, left, top, width, height, rle}]}` with `rle` in Canonical_RLE, and `instance-segmentation-metadata` `{class-map, type: groundtruth/instance-segmentation, objects: [{confidence}], human-annotated, creation-date, job-name}`; consumed by `manifest_to_detector_dataset.py` to write COCO `segmentation` as uncompressed RLE dicts for rfdetr's seg trainer.
- **Canonical_RLE**: DDA's mask encoding — COCO-style uncompressed counts over the column-major flattening, background run first (`dda_manifest.py:42-45`, `rle_encode`/`rle_decode` at `:170-245`), also produced by the Grounded-SAM worker (`grounded-sam-autolabel/requirements.md:89`). **Wire type:** `rle_encode` returns the counts as one space-separated **string** (`dda_manifest.py:170-182`); `rle` in labeling storage and the Instance_Manifest (Requirements 2.2, 3.1) and `mask_rle` in device output (Requirement 10.2) are that string. Only the COCO writer (Requirement 3.3) converts it to a list of ints inside `{"counts": [...], "size": [h, w]}`, the form rfdetr's loader needs; the frontend parser `parseRleCounts(rle: string | number[])` (`components/labeling/AnnotationCanvas.tsx:134`) accepts both, so device, Portal, export and labeling agree without a second conversion.
- **Seg_Stage_Type**: the manifest `model_graph.stages[0].type` that selects the Seg decoder in `MODEL_NAME_MAP` (`model_processors/__init__.py:52-65`). Two values (O16 a): `rf_detr_semantic_segmentation` (kept from `5ebe51bc`; semantic Output_Mode; anomaly-shaped record) and the new `rf_detr_instance_segmentation` (instance Output_Mode; `task = object_detection`). Both map to one decoder class; the stage type implies the mode.
- **Seg_Arch_Key**: `detection_arch = 'rf_detr_seg'`, the new key in every arch-keyed map of `detection_training.py` (O4 b). **Seg_Model_Type**: `model_type = 'instance_segmentation'`, the new value beside `object_detection` and the LFV `segmentation` (O4 b). A Seg record carries both.
- **Seg_Switch**: the single deployment-time configuration value (default ON) that offers or hides RF-DETR-Seg on a Portal deployment (O12 b, Requirement 15).
- **LocalServer_Image**: a device container image carrying the device-side code, built by `build-custom.sh` from one of `src/backend/Dockerfile` (the `amd64` and generic `arm64` CPU components), `Dockerfile.x86_64_nvidia`, `Dockerfile.jp5`, `Dockerfile.jp6`, `Dockerfile.jp7` (derivation table in `scripts/build-target-derivation.sh:30-39`). Five Dockerfiles, six component names.
- **Seg_Feature_Floor**: the per-architecture minimum LocalServer version that carries the Seg device contract — the literal `WORKFLOW_RFDETR_SEG_MIN_LOCAL_SERVER_VERSIONS` read by the Component_Packager and the pre-submit deployment gate (Requirement 14.8), modelled on the stream-camera feature floor `WORKFLOW_STREAM_CAMERA_MIN_LOCAL_SERVER_VERSIONS` (`compute-stack.ts:780-805`; `deployments.py:3490-3501`; `workflow_packaging.py:258-310`). An architecture without an entry fails closed; for JP7 and JP6 the entry is first a *candidate* (entered before the Requirement 18 run, which deploys through the Portal) and then *confirmed* or raised (Requirement 14.8d, enablement order).

## Requirements

### Requirement 1: Shared vocabulary and constants

**User Story:** As a maintainer, I want every Seg constant (sizes, resolutions, stage type, entry point, defaults, licence list) defined once in the shared layer next to the detection ones, so that the training handler, packaging, conversion, Smart Import, frontend mirrors and MCP schemas cannot disagree.

Pattern extended: the arch-keyed maps the RF-DETR spec added to `detection_training.py` (`DETECTION_ARCHES`, `STAGE_TYPE_FOR_ARCH`, `ENTRY_POINT_FOR_ARCH`, `REQUIREMENTS_FOR_ARCH`, `CHECKPOINT_MEMBER_FOR_ARCH`, `DEFAULTS_FOR_ARCH`, `RFDETR_SIZES`, `:42-146`) and the size tables of `detector_conversion.py:120-126` / `export_checkpoint.py:109-121`. No parallel module.

#### Acceptance Criteria

### Requirement 9: Device decoder — instance and semantic modes
