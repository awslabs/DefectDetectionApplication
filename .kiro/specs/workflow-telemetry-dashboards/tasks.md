*Planned 2026-10-17 from `requirements.md` and `design.md` (revision 8), both approved at the owner gate. This spec is implemented **after** `workflow-debug-mode`, whose plan (`.kiro/specs/workflow-debug-mode/tasks.md`) builds the shared device-side modules, the shared Portal package, the lifecycle script and the IAM-gate pattern this plan extends. Section numbers "§x" point into this spec's `design.md`; "B §x" into the debug design.*

## Conventions

The conventions of the debug plan apply unchanged and are not repeated in full here: `$REPO` and `$D` (the uncommitted evidence directory named in the build brief; this plan writes under `$D/dashboards/<task>/`), the two commit rules (Portal code, CDK and docs are committed locally once their tests pass, CDK after `cdk synth`; edge code under `src/` and `test/backend-test/` outside `security/baselines/` is implemented and unit-tested but **never committed, built or deployed**, kept uncommitted in the worktree with patch snapshots under `$D/edge-wip/`), the staged-edge guard before every commit, the hygiene checks on every commit, the hard constraints (no deploy, no AWS write, no device, no build, no push, no rebase) and the five test lanes with their commands (edge host lane on CPython 3.9 with `awsiot` stubbed through `sys.modules`; the Python 3.11 docker lane for `edge-cv-portal/backend/tests`; the host IAM gate; CDK with `npx tsc --noEmit -p .`, `npx jest --ci` and `npx cdk synth ... -o $D/...` under the fixture context; frontend `npx vitest run` and `npm run build`). Baseline counts are the ones `$D/baseline.md` records (debug plan task 0.2) **plus** the debug plan's own additions, which `$D/debug/summary.md` lists.

**What already exists when this plan starts** (built by the debug plan; use unchanged, extend only where a task below says so): `src/backend/workflow_engine/telemetry/{__init__,hooks,publisher,control_shadow,registry_view,topics}.py` and the engine hook points (`pipeline_executor.py`, `trigger_runtime.py`, `continuous_runner.py`, `output_bindings.publish_via_ipc`, `run_log.CAPTURE_FILTERS`); `edge-cv-portal/backend/functions/edge_telemetry_common/{topics,topology,credentials,session_policies,devices,identity,shadow_pool}.py`; `backend/functions/telemetry/{__init__,retention}.py` and `scripts/telemetry_lifecycle.py` (three rule ids); `shared_utils.assume_usecase_role(..., session_policy=None)`; `backend/tests/test_telemetry_credentials_ast.py`; the `usecase-account-stack.ts` helper `addTelemetrySharedStatements(role, account)` with the Sids `TelemetryMediaRetentionRead` and `TelemetryConventionRuleRead`; the IAM-gate pattern for a new stack (debug task 4.3).

## Decisions made in planning (recorded here; the design is not changed)

- **Q1. Extensions only, no surface changes.** This plan adds the purposes `api-control`, `media-read(bucket, usecase)` and `live-expiry(bucket, usecase)` to `edge_telemetry_common/session_policies.py` (§14.4) and `media_retention_ready(rules, versioning)` to `telemetry/retention.py`; every other shared file is used as it is. The surface test `test_telemetry_shared_modules_surface.py` (§5.2) is written here, from the four shared device modules exactly as the debug plan built them, so a later addition to any of them fails a test.
- **Q2. One Portal `topics.py`.** The ingest imports `edge_telemetry_common.topics`; no `telemetry/topics.py` is created (debug plan decision P2).
- **Q3. The desired-state application of the `dda-workflow-telemetry` shadow lives in a new module `telemetry/desired_state.py`** (§5.4's validation, clamping, the lease rules, the eight-entry survivor rule and the `reported` document), because the design places it in no named module and `agent.py` should stay wiring only.
- **Q4. Deployment values** (§15.2) are CDK props with defaults, range-checked at synth and passed to the functions as environment strings; the frontend reads `telemetryNowPollSeconds` and the cadence table from `GET /telemetry/schemas`.
- **Q5. API Gateway resource count** cannot be read without AWS; task 4.1 counts the stack's `addResource` calls (18 expected, §11.2) and records the number for RB-1.
- **Q6. The lake bucket name** is derived in `shared_utils.portal_owned_buckets()` as `edgecv-portal-telemetry-<PORTAL_ACCOUNT_ID>-<AWS_REGION>` from the environment the shared layer already reads, so no new environment key is needed for the derivation (the functions also receive `TELEMETRY_LAKE_BUCKET` for their own writes).
- **Q7. The edge patch snapshot is cumulative** (`git diff -- src/ test/backend-test/` includes the debug plan's edge changes); `$D/edge-wip/dashboards.status` lists the files this plan added or changed.
