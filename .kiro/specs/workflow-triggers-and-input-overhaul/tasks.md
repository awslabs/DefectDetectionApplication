- [x] 0.2 Spike the `opcua` client's subscription/monitored-item support on a real device — per the #7 resolution, spike TRUE subscriptions first: the spike **validates the subscription path** (does the packaged client do reliable data-change subscriptions at the edge?) and **characterizes when the runtime auto-fallback to polling should trigger**. If the spike shows subscriptions are unreliable at the edge, polling becomes the practical default — but the polling fallback (`mode` param `subscribe`|`poll`, `poll_interval_ms`, auto-fallback surfaced in health) is a REQUIRED capability of `opcua_subscribe` regardless of spike outcome (criteria 3.5, 3.6). Spike Greengrass IPC `SubscribeToIoTCore` message-callback behavior + subscribe accessControl. **DONE (2026-08-05, on ryan-orin-nano JP6 v1.0.50 flask-app container):**
  - **OPC UA subscriptions WORK at the edge.** Packaged client is `python-opcua 0.98.13` (sync lib; `asyncua` NOT present). Local server + client `create_subscription(100ms)` + `subscribe_data_change` monitored item: 10/10 data changes delivered in order, latency min 2.9 / avg 13.5 / max 27.2 ms. **`subscribe` stays the default mode.**
  - **Auto-fallback characterization (the key finding):** when the OPC UA server dies, the subscribed client receives **NO signal** — no callback, no exception, the subscription just goes silent; loss only surfaces as `TimeoutError` on the next read and `BrokenPipeError`/`CancelledError` on channel operations. Therefore the runtime MUST run an **active liveness watchdog** per subscription (periodic keepalive read or server-status monitored item); auto-fallback/reconnect triggers on (a) failed initial `create_subscription`/monitored-item setup, (b) keepalive timeout / broken channel (`TimeoutError`, `BrokenPipeError`, `ConnectionError`, `CancelledError`), NOT on waiting for a callback error that never comes. Reconnect must tear down and rebuild the whole client session (channel is unrecoverable after break).
  - **Greengrass IPC `SubscribeToIoTCore` WORKS from the backend container** (SVCUID + `/aws_dda/greengrass/v2/ipc.socket` are available in-container): subscribed to authorized shadow topic `$aws/things/ryan-orin-nano/shadow/name/spike/update`, published 3 messages via IPC, all 3 arrived through `on_stream_event` callbacks. Confirms the callback-based trigger path needs no polling.
  - **Subscribe accessControl is enforced and currently blocks workflow topics:** `SubscribeToIoTCore` on `dda/spiketest` → `UnauthorizedError`. Current recipe only authorizes subscribe on `$aws/things/*/shadow/name/*`. **B.4 (packager adds `aws.greengrass#SubscribeToIoTCore` accessControl for subscribed topics + denial diagnostics) is REQUIRED, confirmed by spike.**
