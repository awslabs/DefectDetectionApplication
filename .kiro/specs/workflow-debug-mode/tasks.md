## Conventions

- **`$REPO`** is the worktree root (`git rev-parse --show-toplevel`); every command runs from there unless stated. **`$D`** is the delivery workflow's uncommitted evidence directory named in the build brief (outside the repository; never committed, never written into a committed file). Each task writes its logs under `$D/debug/<task>/`.
- **Two classes of code, two commit rules** (`.kiro/steering/builds.md`, build brief):
  - **Portal code, CDK and docs** (`edge-cv-portal/...`, `docs/...`, the IAM baselines under `test/backend-test/security/baselines/`): commit locally on `feature/workflow-telemetry-dashboards` once the task's tests pass; CDK changes additionally need `cdk synth` (task 4.4). Stage by explicit path (`git add <paths>`), never `git add -A` or `git add .`.
  - **Edge (LocalServer) code** (`src/backend/...`, `src/frontend/...` and its tests under `test/backend-test/...`): implement and unit-test, but **do not commit, build or deploy**. Decision (planning): the edge changes stay **uncommitted in the worktree**, and every edge task ends with a patch snapshot `git -C $REPO diff -- src/ test/backend-test/ > $D/edge-wip/<task>.patch` plus `git status --porcelain -- src/ test/backend-test/ > $D/edge-wip/<task>.status`, so nothing is lost and the report can list it. A local WIP branch was not chosen: switching branches in the one worktree would carry the uncommitted Portal work along and force rebases of the WIP branch after every Portal commit. **Guard before every commit:** `git -C $REPO diff --cached --name-only | grep -E '^(src/|test/backend-test/)'` must print nothing (the IAM baselines under `test/backend-test/security/baselines/` are the one exception and are staged by name).
- **Hygiene on every commit** (added lines of `git diff --cached -U0` and the message): `python3 /home/ubuntu/dda-tmp/security-scan-d5f01064/label_swap.py --check -` exits 0; the wording grep and the identifier greps of the build brief find nothing (12-digit ids other than the fixture ids `111111111111`, `222222222222`, `333333333333`, `444444444444`, `123456789012`; IPv4 literals; hostnames; thing names; bucket names; IoT endpoints; e-mail addresses other than `@example.com`; registry URIs; paths under `$D`). Hardware model names and neutral wording are fine. Record each commit's hygiene output under `$D/debug/commits/<short id>.txt`.
- **Hard constraints:** no deploy of any kind, no AWS resource creation, no device access, no component build, no push, no rebase. Read-only AWS calls are not needed by any task below.
- **Test lanes** (all verified on 2026-10-17 in this worktree; node v20.20.2, npm 10.8.2):
  - **Edge unit tests (host, CPython 3.9.5, pytest 8.4.2, hypothesis 6.141.1; boto3, Pillow and SQLAlchemy present, `awsiot` absent):** `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src/backend:test/backend-test:test/backend-test/workflow_engine python3 -m pytest <files> -q -p no:cacheprovider` (the root `test/backend-test/conftest.py` fakes `gi` and `dda_logging.logger`; wrap long runs in `timeout`). `awsiot` is stubbed per test through `sys.modules` as `test/backend-test/workflow_engine/test_denial_health_race_exploration.py` (fixture `awsiot_stubs`) and `test_mqtt_publish_retain.py` do. **Edge code must stay importable on 3.9** (no PEP 604 unions or `match` in runtime code; the device runs 3.10/3.11). ## Decisions made in planning (recorded here; the designs are not changed)

- **P1. Shared modules are built here, extended by the dashboards.** `src/backend/workflow_engine/telemetry/{hooks,publisher,control_shadow,registry_view,topics}.py`, the engine hook points, the `publish_via_ipc` factoring, `run_log.CAPTURE_FILTERS`, `edge-cv-portal/backend/functions/edge_telemetry_common/`, `telemetry/retention.py`, `scripts/telemetry_lifecycle.py` and the `session_policy` keyword on `shared_utils.assume_usecase_role`/`get_s3_client_for_bucket` are created by this plan exactly as D §5.2, §2.2, §2.3, §10.2, §12.4 and §14.4 define them (D-F, R1.3). The dashboards plan adds its own purposes, measures and agents and changes none of their surfaces.
- **P2. One Portal copy of `topics.py`.** `edge_telemetry_common/topics.py` is the Portal copy that the device copy `workflow_engine/telemetry/topics.py` must equal byte for byte; no second `telemetry/topics.py` is created (a third copy would have no owner, D §2.2).
- **P3. Two-copy identity tests live in the edge test tree.** The byte-identity tests for `topics.py` and `redact.py` compare a committed Portal file with an uncommitted device file, so they live beside `test/backend-test/workflow_engine/test_vendored_catalog_mirror.py` (the existing Portal-versus-vendored comparison) and stay uncommitted with the edge code until the device phase; a committed Portal test would fail on a clean checkout where the device file does not exist yet.
- **P4. The debug API's region probe runs through the `image-read` credential path.** R5.1 and §3 route the `ListObjectsV2` region probe through `media-retention-read`, whose session policy and whose API-role grants (§9) carry no `s3:ListBucket`; the probe would be denied in both topologies. The probe therefore uses `ListObjectsV2(Prefix='dda-telemetry/debug/<usecase_id>/', MaxKeys=1)` through `credentials.client('s3', U, 'image-read')`, whose `s3:ListBucket` is conditioned on exactly that prefix in both topologies, and reads the `x-amz-bucket-region` header first with the use case's region as the fallback and `region_source` reported, unchanged. Recorded for the report as an open question against the design text.
- **P5. The LocalServer deployed-workflows badge (R2.7) is implemented only if the LocalServer frontend toolchain is already installed** (`src/frontend/node_modules`); it is optional for the first release. The device run API's `debug` field is implemented regardless.
- **P6. Evidence of every lane goes to `$D`**, counts and failing ids only; the report step reads it.
