# Implementation Plan

## Overview

This plan follows the bug-condition methodology. Any base-image `FROM` line in an
in-scope Dockerfile (`src/backend/Dockerfile.jp5`, `src/edgemlsdk/Dockerfile.jp5`,
`src/backend/Dockerfile.jp6`, `src/edgemlsdk/Dockerfile.jp6`) that pulls from the
external, non-ECR registry `nvcr.io` and is either NOT registry-parameterized
(the registry is a literal, not `${BASE_REGISTRY...}`) OR NOT pinned to an
immutable `@sha256` digest is the bug (`isBugCondition(X)` true). Per the user's
**Option A** decision the fix is **registry parameterization via a build `ARG`
(`ARG BASE_REGISTRY=nvcr.io` before the first `FROM`) + immutable `@sha256` digest
pinning with the human-readable tag and any `AS <stage>` name retained**, **NOT**
a relocation of the NVIDIA-proprietary Jetson images to ECR (Option C rejected —
DDA does not own them and there is no public-ECR equivalent). The three pinned
digests are the multi-arch **manifest-list** digests the current mutable tags
resolve to on `nvcr.io`, so per-arch selection is unchanged and pinning is
behavior-preserving for the default build (`F(X) = F'(X)`). Docker scopes an
`ARG` declared before the first `FROM` to every subsequent `FROM` without
re-declaration, so `Dockerfile.jp6` gets a single shared `ARG BASE_REGISTRY`
covering both its `FROM`s and **no** post-`FROM` `BASE_REGISTRY` re-declaration is
added. Only the `FROM` line(s) change, plus exactly one added
`ARG BASE_REGISTRY=nvcr.io` line per file; every other line is byte-for-byte
unchanged.

- **Property 1: Fix Checking** — for all inputs where `isBugCondition` is true,
  every in-scope `FROM` is registry-parameterized via `${BASE_REGISTRY}` (with
  `ARG BASE_REGISTRY=nvcr.io` before the first `FROM`) AND digest-pinned with
  `@sha256:`, retaining its tag (`r35.4.1` / `r36.3.0` / `11.4.19-runtime`) and
  any `AS <stage>` name (`builder` / `cuda114`), and the repo audit returns zero
  disallowed hits (Requirements 2.1–2.6).
- **Property 2: Preservation** — for all inputs where `isBugCondition` is false,
  `F(X) = F'(X)` — the default build (`BASE_REGISTRY` unset/`nvcr.io`) pulls the
  identical image bytes (the pinned digest IS the manifest-list digest the tag
  resolves to), every non-`FROM` line in all four Dockerfiles is byte-for-byte
  identical, the `AS builder` / `AS cuda114` names and the `COPY --from=cuda114`
  reference still resolve, no `docker-compose.yaml` change is required, and the
  already-compliant `public.ecr.aws/*` Dockerfiles plus the vendored
  `src/backend/edgemlsdk/edgemlsdk/…` duplicate are unchanged (Requirements
  3.1–3.7).
