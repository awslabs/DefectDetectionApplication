# Implementation Plan

## Notes

- Every existing publish must stay byte-identical. The Publisher_Call preservation
  suites (`test_mqtt_publish_call_preservation.py`, `test_mqtt_greengrass_dispatch.py`,
  `TestMqttPublish*`, `TestMqttSentDetail`) are run green on the unchanged tree
  first (task 2.1) and again after every edge edit; they are never modified.
- The catalog source of truth is the portal layer
  (`edge-cv-portal/backend/layers/workflow_core/python/workflow_core/catalog/nodes.py`).
  The edge copy is generated by `src/backend/workflow_engine/vendor/re_vendor.sh`
  and sha256-pinned by `test_vendored_catalog_mirror.py`; never hand-edit the mirror.
- `catalog_baseline.json` is NOT touched: the `mqtt_publish` entry is bug-condition
  evidence and its preservation tests only pin parameters present in the baseline
  (see task 1.3 and `src/backend/workflow_engine/vendor/README.md`).
- Exactly two existing tests change on purpose: the parameter-name list in
  `test_unified_input_descriptor.py::test_mqtt_publish_category_ports_and_parameter_names`
  and the `MQTT_PUBLISH` fixture in `NodeConfigPanel.test.tsx`. Anything else
  turning red is a regression, not a rebaseline candidate.
- No IAM change. `iot:RetainPublish` is an IoT data-plane action and goes only into
  IoT policies (`device_provisioning.py`, the README examples), on topic-scoped
  resources, never `"Resource": "*"`.
- `output_bindings.py` runs on device: the edge change is not done until a
  LocalServer built from it is verified on real hardware (task 8). Follow
  `.kiro/steering/builds.md` before the build (pgrep, preservation suite incl. the
  IAM out-of-scope guard, cdk.out moved aside). JP7 builds go through the portal
  build fleet from a pushed branch (see memory "How to actually build + deploy a
  LocalServer change for JP7").
- Test commands:
  - Edge (repo root): `PYTHONPATH=src/backend:test/backend-test python3 -m pytest test/backend-test/workflow_engine/<file> -q -p no:cacheprovider`
    (host lacks fastapi etc.; run inside the flask-app container when the suite imports the app)
  - Portal layer (from `edge-cv-portal/backend/layers/workflow_core`): `python3 -m pytest tests/<file> -q -p no:cacheprovider`
  - Portal functions (from `edge-cv-portal/backend`): `python3 -m pytest tests/<file> -q -p no:cacheprovider`
  - Frontend (from `edge-cv-portal/frontend`): `npx vitest run src/pages/workflows/NodeConfigPanel.test.tsx`, `npm run build`
  - Preservation (repo root): `python3 -m pytest test/backend-test/security/preservation -q -p no:cacheprovider --noconftest --ignore=test/backend-test/security/preservation/test_preservation_deserialization_roundtrip.py`
- The WSL shell tool is shared with other sessions and drops output; redirect every
  command's output to a file and read it back.
