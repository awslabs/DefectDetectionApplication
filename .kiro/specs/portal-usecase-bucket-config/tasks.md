# Implementation Plan

## Notes

- Portal only: `edge-cv-portal/backend`, `edge-cv-portal/infrastructure`, `edge-cv-portal/frontend`, `edge-cv-portal/*.md`, repo `README.md`. Nothing under `src/`, `station_install/` or `hmi/` changes; no LocalServer build and no on-device verification is owed (the lab workstation is powered off and is not needed). If a task appears to need device code, stop and ask.
- Wording: every commit message, comment, docstring, test name and document describes the feature (use-case bucket configuration; S3 access resolved through the use case's configured buckets) and never points at material outside the repository. Suggested commit message: `feat(portal): resolve S3 access through the use case's configured buckets`.
- **State directory.** `$D` is the uncommitted state directory for this spec (outside the repository; its path and the lane wrapper are defined once in `verification-notes.md`, Environment). Scripts, logs, CDK diffs, sizing output and secrets of the runbook live there, never under the repository. `$REPO` is the worktree root (`git rev-parse --show-toplevel`).
- **Test commands.** Host Python is 3.9 and cannot import the shared layer; use the Python 3.11 lane wrapper `$D/portal_py` from the worktree root:
  - Backend, targeted files only, never all of `tests/` in one process: `HYPOTHESIS_PROFILE=ci $D/portal_py -m pytest edge-cv-portal/backend/tests/<file> -q -p no:cacheprovider`.
  - Frontend: `npx vitest run <file>` then `npm run build` in `edge-cv-portal/frontend`.
  - CDK: `npm test -- <file>` in `edge-cv-portal/infrastructure`.
  - Security suites (host python3 is fine): see `verification-notes.md` §Baseline.
- **Preservation.** `compute-stack.ts` changes the synthesised EdgeCVPortalComputeStack by exactly three statements on the UseCases role. Record them in `test/backend-test/security/baselines/iam_post_fix_approved_additions.json` (attribution: this spec) and regenerate `iam_baseline_EdgeCVPortalComputeStack.template.json` per the docstring of `test_preservation_iam_cdk_synth.py`. `model_converter.py` is pinned byte-for-byte in `iam_out_of_scope_baseline.json` and must be rebaselined (task 9.0). The vendored `urllib3` tree is pinned by `test_preservation_dependency_out_of_scope.py`: install the SDK with `--no-deps` (task 1.0). Do not touch the `createLambdaRole` I2 block. Move `cdk.out` aside before running the guard pair (`.kiro/steering/builds.md`).
- **Deploy rules.** Never run a portal deploy while a component build is running (`pgrep -af "gdk component build"` and `pgrep -af "build-custom.sh"` must both be empty). Deploy includes a CDK diff (IAM on the UseCases role) plus a SharedLayer bump (now ~25 MB larger: vendored SDK) and the affected functions. Section 11 is an executable runbook: the owner has approved running every task including the deploy, the post-deploy verification and the trunk push (`$D/owner-go-ahead.md`); it stops and asks only where a pre-check fails.
- Grandfathering (Req 8): do not add compile/package-time re-checks of stored `artifact_s3`.
